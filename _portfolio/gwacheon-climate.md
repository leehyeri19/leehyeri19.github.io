## 📌 프로젝트 개요
* **프로젝트명**: 과천시 기후환경 관리시스템
* **수행 기간**: 2024.01 ~ 2024.06
* **담당 역할**: Redis 캐싱 아키텍처 설계 및 실시간 백엔드 관제 API 개발
* **도메인**: 공공 환경·기후 인프라 및 실시간 센서 관제
* **기술 스택**: `Java`, `Spring Boot`, `Redis`, `MySQL`, `Linux`, `Docker`

---

## 🔍 문제 상황 (Problem)
1. **긴급 기후 이상 징후에 대한 초동 대응 지연**:
   * 기존 시스템은 관제 화면에서 **1분(60초) 주기 HTTP Polling 방식**을 사용하고 있었습니다.
   * 이에 따라 폭우 침수, 미세먼지 수치 급증 등 긴급 기후 이상 징후 발생 시 **최대 60초의 정보 지연**이 발생하여 골든타임 내 긴급 알림 및 현장 초동 대응이 지체되는 한계가 있었습니다.
2. **반복적인 RDBMS 읽기 쿼리 병목**:
   * 종합상황실 및 다수 관제 클라이언트에서 동시에 1분 주기로 동일한 센서 데이터를 전체 조회하여, RDBMS에 불필요한 단순 읽기 부하가 상시 누적되었습니다.

---

## 💡 해결 방법 (Solution)
1. **Redis 인메모리 캐시 레이어 설계 및 구축**:
   * 센서 데이터 인입 즉시 메모리에 최신 상태를 유지하도록 **Redis Key-Value 캐시 파이프라인**을 구축하였습니다.
   * 데이터 갱신 시 캐시를 즉시 업데이트하고, 적절한 유효시간(TTL) 정책을 적용하여 메모리 효율성을 유지했습니다.
2. **관제 API 조회 경로 전환**:
   * 관제 화면 클라이언트의 요청이 무거운 RDBMS를 직접 거치지 않고, Redis 인메모리 캐시에서 직접 서브세컨드(Sub-second)로 데이터를 조회하도록 백엔드 조회 경로를 분리 및 전환하였습니다.

---

## 📈 정량적 성과 (Impact)
* ⚡ **데이터 표출 지연 시간 98% 단축**: **최대 60초 ➔ 1초 미만**으로 대폭 단축하여, 긴급 기후 이상 발생 시 즉각적인 초동 대응 환경을 확보했습니다.
* 🛡️ **RDBMS 단순 읽기 부하 80% 이상 절감**: 반복 쿼리 병목을 해소하여 데이터베이스의 전반적인 가용성 및 시스템 안정성을 극대화했습니다.
